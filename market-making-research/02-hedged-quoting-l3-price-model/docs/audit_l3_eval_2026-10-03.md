# 逐笔委托评估审计(2026-10-03)

起因:用户看完 PX-5 后指出"结论已经完全反直觉和反业内共识,你绝对哪个地方做错了"。审计结果:**确有三处方法错误**,QMM-1/2、PX-2、PX-3、PX-5 文档中的原数字作废,以本文件与各 `*_fix.txt` 为准。

## 错误 1:成交后收益用的中间价有断档(数据错误)
- 所有逐笔委托检验的 markout 都用 `qmm_l3_study.bbo(day)`:由另一路 L2 录制重建的买一 / 卖一。该录制 10-01 有 121 次 > 5 秒的断档,最长 33 分钟;断档期间序列停在旧价。
- 10-01 的 14、15 点(开发日成交最多的两小时)分别有 19% / 33% 的时间偏差 > 1 bp(最大 40 bp)。15 点 QMM 成交的 10 秒 markout 原为"均值 +0.96、标准差 20 bp",实为 −2.07 / 3.8。10-01 全天不撤单 −1.21 → −1.71 bp。10-02 基本不受影响(18、19 点各 2–4%)。
- 后果:10-01 是选参数和做诊断的开发日 → PX-2 / PX-3 选出的门槛、"挂上 <20 ms 成交亏 4–7 bp、> 1 s 赚 4–7 bp"等诊断都建立在错误数据上。
- 修正:`scripts/research3/l3_mid.py`(逐笔委托 2 ms 网格自身的中间价;与原序列在正常时段逐点一致),已接入 `qmm_state.load`、`px_cancel.load_traces`、`px5_eval.load`。
- 本该更早发现:逐笔 10 秒 markout 的 10% / 90% 分位 ±10 bp,而 BTC 10 秒收益标准差只有 1–4 bp;当时被解释成"急动小时的运气"。

## 错误 2:重叠挂单被当作独立样本(口径错误)
- 虚拟单每秒(PX-5)或每个新价位(QMM)放一张、活 5–10 秒,同侧同时有多张;录制里没有任何吃单跨两个价位成交,一笔小卖单会把所有活着的虚拟买单同时"成交"。
- 修正:`scripts/research3/px6_single.py`(每侧同时只有一张,结束后才挂下一张)。影响比预想小:排队尾不撤单 −0.83 / −0.87 → −0.89 / −0.90;带盾 −0.43 / −0.58 → −0.48 / −0.60。

## 错误 3:用"无穷小订单、按笔数平均"评估做市(方法错误,最重要)
用不依赖虚拟单规则的办法对照:逐笔委托里每一条 match 就是一笔真实挂单成交(`scripts/research3/real_maker.py`,10-01 3.0 万笔 / 1,160 BTC,10-02 8.1 万笔 / 2,844 BTC,10 秒 markout + 我方费率)。

| | 10-01 | 10-02 |
|---|---|---|
| 全部真实挂单成交,**按成交量加权** | +0.25 bp(7/11 小时为正) | +0.40(15/22) |
| 同上,按笔数 | −0.09 | −0.18 |
| 同上,每笔按我们的单量封顶 0.06 BTC | −0.08 | −0.21 |
| 吃单 ≤ 100 张(0.1 BTC)的成交,按量 | −0.23(1/11) | −0.38(3/22) |
| 吃单 100–500 张 | −0.48(1/11) | −0.42(7/22) |
| 吃单 > 500 张(0.5 BTC) | +0.76(9/11) | +1.13(16/22) |
| 吃单 > 2,000 张(2 BTC) | +1.20(11/11) | +2.11(18/22) |
| 创造新最优价的挂单,按笔数 | +0.41(9/11) | +0.31(20/22) |
| 加入最优价的挂单,按笔数 | −0.00 | −0.13 |
| 我方虚拟单"加入队尾、不撤"(PX-5 / PX-6) | −0.83…−0.89 | −0.87…−0.90 |

读法:
1. **真实做市商在这个合约上是赚钱的(按量 +0.25…+0.40 bp),钱来自接大吃单**:吃单越大,挂单方越赚(大单之后价格回吐);小吃单才是有毒的。这与"队尾只会被大单吃到、大单有信息"的假设相反,也与我之前的结论相反。
2. 无穷小虚拟单拿不到大吃单的"量":大吃单给一张真实挂单的是整张单的量,给无穷小单的只是"一笔";按笔数平均时,小而毒的吃单权重被放大。做市盈亏是按量结算的,应当用**有单量的挂单、按量加权**评估。
3. 同一位置(加入最优价)真实挂单每笔约 −0.0…−0.13,虚拟单 −0.85:差距来自虚拟单从不撤(价位上别人都撤光了它还在,随后被打穿——这类"被打穿"的成交占虚拟成交的四到七成),以及第 2 点。
4. 按量为正的结果尾部很重(收益最大的 1% 成交占 |盈亏| 的 28–41%,按小时 t 只有 1.2–2.9),不能直接当可实现收益;但方向明确。
